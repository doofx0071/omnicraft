# Template engine

How OmniCraft turns `Answers` into a generated project. Source: `packages/cli/src/scaffold/`
(`compose.ts`, `engine.ts`, `renderer.ts`, `merge.ts`). Template tree: `packages/cli/templates/`.

For the layer kinds, required files, and what belongs where, see the [template contract](../templates/template-contract.md).

## 1. Composition: Answers → ordered layers

`composeLayers(answers)` returns an ordered `Layer[]`, where a layer is `{ src, dest }` — `src` relative
to the templates root, `dest` relative to the target directory.

Layer order (each stage may overwrite or merge into earlier output):

1. **Client** — `web/react/client` → `client/` (full-stack) or `.` (frontend-only).
2. **Server base** — `server/node/<framework>/base` → `server/` (node only).
3. **Database adapter** — `db/<orm>/<database>` (node) or `db/sqlalchemy/<database>` (python) → `server/`.
4. **Framework×ORM wiring** — `server/node/<framework>/<orm>` → `server/` (node only; routes/env that
   reference the chosen ORM).
5. **Extras** — `extras/tailwind` → client dest, `extras/eslint` → `.`.
6. **Root variant** — `root/fullstack[-python|-php]/<database>` or `root/frontend-only` → `.`.

### The Laravel exception

Laravel templates are **overlays**. `isPostComposerLayer()` identifies `server/php/...` layers; the CLI:

1. Applies all non-post layers first.
2. Runs `composer create-project laravel/laravel:^12.0 server` in the target.
3. Applies the overlay layers (copying over the Composer skeleton).
4. Copies `server/.env.example` → `server/.env` and runs `php artisan key:generate --force`.

Reason: a Laravel skeleton is generated by Composer's own installer; the overlay assumes it exists.

## 2. Layer application (`applyLayer`)

For each layer, the engine lists `templatesRoot/<src>` **recursively** and, for every file:

1. **Dotfile restore** — every path segment starting with `_` gets a dot: `_gitignore` → `.gitignore`,
   `_github/` → `.github/` (npm won't reliably publish those otherwise). `.env.example` ships as-is.
2. **Destination resolve** — `targetDir/<dest>/<renamed path>`; directories are created recursively.
3. **Binary check** — by extension list (images, fonts, media, archives); binaries are copied verbatim.
4. **Render** — text files get token substitution.
5. **Manifest merge** — if the destination file is `package.json` **and already exists**, the rendered
   content is deep-merged into it (see §4) instead of overwriting.

A missing layer directory throws `MissingLayerError` (fail fast, before any later layer runs).

**Current overwrite semantics (honest statement):** same-path files from later layers silently replace
earlier ones (except `package.json`, which merges). This is a **feature the template tree relies on** —
e.g. `src/routes/index.ts`, `src/env.ts`, `vite.config.ts`, `src/index.css`, and `.env.example` are
intentionally provided by a base layer and _overridden_ by an ORM/db/extras layer. Do not "dedupe" them.
The master plan (§4.2) proposes making collisions explicit with declared strategies; until that lands,
any new layer must be written knowing it may override and be overridden.

## 3. Token rendering

`renderString(input, variables)` replaces `{{ token }}` (whitespace-tolerant) using the variables from
`templateVariables(answers)`:

| Token                   | Value                                                      | Used for                               |
| ----------------------- | ---------------------------------------------------------- | -------------------------------------- |
| `{{projectName}}`       | slugified app name                                         | titles, compose project name, README   |
| `{{clientPackageName}}` | `<name>-client` (full-stack) or `<name>`                   | client package.json name               |
| `{{serverPackageName}}` | `<name>-server`                                            | server package.json name               |
| `{{databaseName}}`      | name with dashes → underscores                             | Postgres/MySQL DB identifiers, compose |
| `{{backendFramework}}`  | `express` \| `fastify` \| `hono` \| `fastapi` \| `laravel` | generated README tables                |
| `{{orm}}`               | `drizzle` \| `prisma` \| (empty)                           | generated README tables                |
| `{{dbConfig}}`          | Laravel-only multi-line DB env block                       | `server/php/laravel/.env.example`      |

**Unknown tokens are left untouched today** (not an error). Tests assert no known token leaks into any
generated file. The master plan (§4.3) proposes failing on unresolved tokens; if you implement that, keep
`{{dbConfig}}` (composed in `templateVariables`) valid in every database branch.

## 4. Manifest merging

`deepMergePackageJson(base, override)`:

- Plain objects merge recursively (deps, scripts, workspaces…).
- Scalars and **arrays** from the override replace the base's.

This is why every layer can ship a _partial_ `package.json` — e.g. the db layer adds
`dependencies.drizzle-orm` and `scripts.db:push`, the root layer adds workspaces + `concurrently`, the
extras layer adds eslint deps + lint scripts — and the final manifest is the union. `npm ci` consumes the
result; CI's e2e step proves the merged manifests actually install and typecheck.

Known sharp edge (documented, currently accepted): the generic merge means a later layer can silently
replace a script with the same name. Template authors must pick distinct script names or intend the
override (the db layers' `db:*` scripts are the convention).

## 5. Failure handling

- `MissingLayerError` — composition referenced a template that doesn't exist (broken `compose.ts` or
  renamed directory). Surfaces immediately with the layer name.
- Destination is a non-empty directory → interactive confirm; `--yes` refuses outright (never scaffolds
  over existing files non-interactively).
- Install/uv/composer failures are non-fatal to the generated files: the CLI reports the failure, prints
  the manual command, and still shows next steps.
- `restoreTerminal()` runs on every exit path so clack's raw mode can't garble the terminal.
